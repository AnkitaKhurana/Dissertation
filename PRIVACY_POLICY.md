# Privacy Policy — PR Sentinel Chrome Extension

**Last Updated**: January 20, 2026

**PR Sentinel** ("we", "our", or "the extension") respects your privacy. This Privacy Policy explains how PR Sentinel collects, uses, and protects your information when you use our Chrome extension.

---

## 1. Information We Collect

### 1.1 User-Provided Information

- **GitHub OAuth Token**: When you authenticate with GitHub, we receive an OAuth token that allows us to access your GitHub profile and pull request data on your behalf. This token is stored securely in your browser's session storage by default.
- **LLM API Keys and URLs**: If you choose to provide your own LLM API keys or local LLM URLs, these are stored in your browser's session storage by default and are **never sent to our servers** unless you explicitly opt in to persist them.
- **User Preferences**: Theme settings, agent configurations, and display preferences are stored locally in your browser.

### 1.2 Automatically Collected Information

- **PR URLs**: When you request an analysis, we send the GitHub PR URL to our backend server to fetch the PR diff and perform analysis.
- **Analysis Results**: Findings and suggestions generated by our LLM agents are stored temporarily in our database and associated with your user account.
- **Usage Logs**: Our backend logs API requests (without source code or diffs) for debugging and performance monitoring purposes. Logs include timestamps, user IDs, job IDs, and error messages but **do not include API keys, tokens, or source code**.

### 1.3 Information We Do NOT Collect

- **Source Code Content**: We do not store or log the actual source code from your pull requests. PR diffs are processed in memory and discarded after analysis.
- **GitHub Credentials**: We never request or store your GitHub username or password. All authentication uses GitHub's OAuth flow.
- **Personal Identifiable Information (PII)**: We do not collect names, email addresses, physical addresses, or phone numbers beyond what GitHub provides via OAuth (GitHub username and profile).

---

## 2. How We Use Your Information

### 2.1 Core Functionality

- **PR Analysis**: We use PR URLs and diffs to perform code review, security, testing, and maintainability analysis via LLM agents.
- **Job Management**: We store job metadata (status, progress, findings) to enable asynchronous polling and offline access to recent jobs.
- **Authentication**: GitHub OAuth tokens are used to verify your identity and associate jobs with your account.

### 2.2 Service Improvement

- **Error Debugging**: Logs help us identify and fix bugs or performance issues.
- **Feature Development**: Aggregated, anonymized usage statistics may inform future feature development (not implemented in current version).

### 2.3 What We Do NOT Do

- **No Selling of Data**: We do not sell, rent, or trade your information to third parties.
- **No Advertising**: We do not use your data for advertising purposes.
- **No Third-Party Analytics**: We do not use third-party analytics services (e.g., Google Analytics) in the current version.

---

## 3. Data Storage and Retention

### 3.1 Local Storage (Browser)

- **Session Storage**: API keys, LLM URLs, and JWT tokens are stored in `chrome.storage.session` by default and are **cleared when you close your browser**.
- **Local Storage**: User preferences (theme, agent settings) and cached job results (last 3 jobs) are stored in `chrome.storage.local` and persist across browser sessions.
- **Opt-In Persistence**: You can choose to enable "Remember my API keys" in the Options page to persist API keys in local storage. This is **disabled by default** for security.

### 3.2 Server Storage (Backend)

- **Database**: Job metadata and findings are stored in MongoDB (MongoDB Atlas for dev, Azure Cosmos DB for production).
- **Retention Periods**:
  - **Free Tier Users**: Jobs are automatically deleted after **1 day** (86400 seconds) via MongoDB TTL index.
  - **Pro/Admin Users**: Jobs are automatically deleted after **5 days** (432000 seconds).
- **Manual Deletion**: You can manually delete individual jobs via the extension UI (feature TODO).

### 3.3 Logs

- **Backend Logs**: Stored for up to **30 days** and then automatically purged.
- **Log Redaction**: Logs are automatically redacted to remove API keys, tokens, and source code snippets.

## 4. Data Sharing and Disclosure

### 4.1 Third-Party Services

We use the following third-party services:

## 5. Data Security

### 5.1 Encryption

- **In Transit**: All communication between the extension and backend uses HTTPS (TLS 1.2+).
- **At Rest**: Database credentials and secrets are stored in Azure Key Vault (production) or encrypted `.env` files (development).

### 5.2 Access Control

- **Backend**: Access to production servers and databases is restricted to authorized personnel only.
- **Extension**: API keys and tokens stored in browser storage are protected by Chrome's built-in security mechanisms.

### 5.3 Security Best Practices

- **No Inline Scripts**: The extension uses a strict Content Security Policy (CSP) to prevent XSS attacks.
- **Session-Only Storage**: Sensitive data (API keys, tokens) is stored in session storage by default and cleared on browser close.
- **Rate Limiting**: API endpoints are rate-limited to prevent abuse.

## 6. Your Rights and Choices

### 6.1 Access and Export

You can view all your analysis jobs and findings via the extension UI. To export your data, contact us at [support@prsentinel.example.com].

### 6.2 Deletion

- **Job Deletion**: Jobs are automatically deleted based on your tier's retention period (1 day for free, 5 days for pro/admin).
- **Account Deletion**: To delete your account and all associated data, contact us at [support@prsentinel.example.com]. We will delete your data within 30 days.

### 6.3 Opt-Out

- **API Key Persistence**: You can disable "Remember my API keys" in the Options page to prevent API keys from persisting across sessions.
- **Hosted LLM Service**: Pro users can opt out of the hosted LLM service and use their own API keys or local LLM instead.

### 6.4 Cookie Policy

We use secure, HTTP-only cookies for authentication (JWT tokens). These cookies are:
- **Secure**: Sent only over HTTPS
- **HttpOnly**: Not accessible via JavaScript (prevents XSS)
- **SameSite**: Set to 'strict' (prevents CSRF)

You can clear cookies via your browser settings, but this will log you out of the extension.
